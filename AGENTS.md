# Agent instructions for unwrapped.tools

Read this file before editing. See `CONTRIBUTING.md` for the project map and contributor workflow.

## Product contract

unwrapped.tools provides developer utilities that run in the browser.

- Tool code runs client-side. Do not add uploads, server-side processing, beacons, tracking,
  analytics, telemetry, accounts, login, sync, ads, or collaboration.
- Do not persist tool inputs or outputs. User preference storage must be registered and described in
  `src/lib/localPersistence.ts`.
- Change this contract before changing product scope. Keep `README.md` and `/privacy` accurate.

## Source of truth

- `src/tools/registry.ts` owns tool metadata and routes. Add each tool there; do not maintain a
  second catalog in docs or scripts.
- `src/lib/` and tool-local modules own business logic. Components collect input, render state, and
  handle user interaction.
- Use `src/lib/fileImport.ts` for user file reads.
- Use `@/` for `src` imports and follow the existing style tokens for UI.

## Working rules

- Install dependencies with `bun install`.
- Run the app with `bun run dev`.
- Run `bun run verify` before opening a PR or pushing changes.
- Work on a branch based on the latest `main`. Do not commit directly to `main`.
- Use Conventional Commit types: `feat`, `fix`, `docs`, `refactor`, `chore`, `test`, `ci`, or
  `build`.

`README.md` is the user-facing quickstart. `CONTRIBUTING.md` is the contributor guide. `CHANGELOG.md`
is generated by release-please. Keep product and privacy claims in sync with the code.
